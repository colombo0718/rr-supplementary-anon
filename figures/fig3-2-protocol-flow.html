The platform (parent page) and the game environment (child iframe) communicate bidirectionally via postMessage
sequenceDiagram participant Game as Child page: game environment (iframe) participant Lab as Parent page: RL Lab platform Note over Lab,Game: Loading phase (triggered once per loadGame) Lab->>Game: questInfo

{ stateInfo, actionInfo } Note over Lab,Game: The platform uses this to build the Q-Table structure and action buttons automatically rect rgb(255, 248, 230) loop Every interaction step: state-action-reward loop Lab->>Game: action
{ action: index } Game->>Lab: reward_state
{ reward, state, done, sessionId } end end Note over Lab,Game: Control messages (may be sent at any time) Lab->>Game: pause / accel
Note: questInfo / action (platform to game); gameInfo / reward_state (game to platform). When done: true, reward must already include the terminal penalty (no separate endEpisode message is sent). sessionId is incremented by the platform on every loadGame, and the game must return it unchanged to avoid cross-session message contamination. This design fully decouples the platform and the game at the code level: any web page that follows this protocol can be loaded as a training environment.
